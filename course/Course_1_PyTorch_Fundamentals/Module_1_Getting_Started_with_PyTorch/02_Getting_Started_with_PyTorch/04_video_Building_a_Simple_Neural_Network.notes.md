# Building a Simple Neural Network

## Источники

- `04_video_Building_a_Simple_Neural_Network.trans.txt`

## Контекст

Ранее были разобраны ML-пайплайн и то, как учатся нейронные сети. Это видео показывает,
как всё это отображается в реальном коде `PyTorch`.

## Импорты

Три базовых импорта дают:

- `torch` — базовая функциональность `PyTorch`;
- `nn` — компоненты для построения нейронных сетей;
- `optim` — инструменты для обучения (тренировки) сетей.

## Данные и тензоры

В реальных проектах data ingestion и data preparation — отдельные шаги: сначала
собираются «грязные» данные, затем они очищаются и форматируются. В этом примере эти
стадии объединены, и данные предоставлены уже чистыми и готовыми к использованию.

Данные создаются из обычных Python-списков, но `tensor` — это больше, чем просто список:
тензоры оптимизированы под вычисления, которые нужны нейронным сетям (подробнее о них —
в следующих двух видео этого модуля). Пока их достаточно воспринимать как контейнеры,
которые хранят и организуют данные в форме, понятной модели.

### Структура вложенных скобок

- Каждое число обёрнуто в свой набор скобок.
- Внешние скобки представляют подмножество всего датасета — набор отдельных точек
  данных. Такая коллекция называется **батчем** (`batch`).
- Каждый внутренний набор скобок — один сэмпл (`sample`) в батче.
- Например, для четырёх записей о доставке будет четыре сэмпла, каждый в своих скобках.
- Поскольку у каждой доставки в этом примере только один признак (расстояние), каждый
  сэмпл содержит только одно значение.
- Если бы входных признаков было несколько (расстояние, время суток, погода), каждый
  сэмпл содержал бы несколько значений — по одному на признак. Скобки показывают
  `PyTorch`, где заканчивается один сэмпл и начинается следующий, независимо от того,
  один признак у сэмпла или сотни.

### dtype

`dtype=torch.float32` указывает `PyTorch`, какой тип чисел хранить — в данном случае
32-битные числа с плавающей точкой, подходящие для десятичных значений времени доставки.

## Построение модели

`Sequential` — это «упорядоченная» версия `PyTorch` (в противоположность жёстким
«сборочным линиям» ранних фреймворков deep learning): контейнер, который пропускает
данные через слои по порядку, но при этом легко позволяет заменять компоненты без
«грязной» перепроводки связей.

В этом примере используется только один слой — единственный нейрон, технически это
**линейный слой** (`linear layer`):

- первый параметр (`1`) означает, что слой принимает один вход — расстояние;
- второй параметр (`1`) означает, что слой производит только один выход — предсказанное
  время доставки;
- слой применяет к входу линейное преобразование, и это всё, что делает линейный слой.

`PyTorch` делает создание таких слоёв простым — они встроены во фреймворк, и создать их
можно одной строкой кода.

Этот нейрон будет учиться находить наилучшие значения веса и смещения, чтобы отображать
расстояния во время доставки — так же, как поиск наиболее подходящей линии через все
точки данных.

## Функция потерь и оптимизатор

Модели нужны два инструмента, чтобы реально учиться:

1. **Функция потерь** (`loss function`) — в примере используется **mean squared error
   loss** (среднеквадратичная ошибка). Она измеряет, насколько предсказания далеки или
   близки к истине. Например, предсказание 45 минут при реальных 60 — большая ошибка,
   чем, скажем, предсказание 58 минут.
2. **Оптимизатор** (`optimizer`) — используется `SGD` (`stochastic gradient descent`,
   стохастический градиентный спуск) — алгоритм, который определяет, в каком направлении
   нужно скорректировать вес и смещение, чтобы уменьшить ошибку.

Детали настройки оптимизатора:

- `model.parameters` — способ получить доступ к параметрам модели в `PyTorch`; в данном
  случае это вес и смещение единственного нейрона.
- `lr` (`learning rate`, скорость обучения) — меньшие значения означают, что вес и
  смещение корректируются меньшими шагами; большие значения означают более крупные
  корректировки. У обеих крайностей есть свои проблемы.

> Более глубокое погружение в математику функций потерь и оптимизации даётся в Module 2,
> а также в ресурсах курса и в специализации Deep Learning.

## Тренировочный цикл (training loop)

Тренировочный цикл — это то место, где происходит фактическое обучение. Он автоматически
повторяет вручную описанную ранее корректировку веса и смещения (движение к более
подходящей линии) — в этом примере 500 раз.

**Определение.** Один полный проход по всем тренировочным данным называется **эпохой**
(`epoch`).

В каждой эпохе модель:

1. делает предсказания;
2. измеряет, насколько эти предсказания далеки от истины;
3. корректирует свои внутренние параметры, чтобы улучшить предсказания.

### Разбор кода тренировочного цикла построчно

- `optimizer.zero_grad()` — обнуляет все вычисленные значения (градиенты) с предыдущего
  раунда обучения. Без этого `PyTorch` накапливал бы корректировки между раундами, что
  испортило бы обучение. Подробнее об этом методе — далее в курсе.
- `outputs = model(inputs)` — говорит модели использовать расстояния как входные данные.
- `loss = loss_function(outputs, times)` — сравнивает предсказания с реальными временами
  и вычисляет, насколько сильно они ошибаются.
- `loss.backward()` — вычисляет, как нужно скорректировать вес и смещение, чтобы
  уменьшить ошибку («нужен более крутой наклон» — теперь это делается математически, с
  помощью calculus «за кулисами»). Технический термин для этого процесса —
  **backpropagation** (обратное распространение ошибки).
- `optimizer.step()` — применяет все эти корректировки.

## Инференс

После обучения модели можно делать предсказание. Строка с `torch.no_grad()` сообщает
`PyTorch`, что обучение больше не идёт — выполняется только инференс (`inference`).
Тренировка требует дополнительной работы «под капотом», но для инференса эту работу можно
пропустить и работать намного эффективнее.

Если модель научилась тому, чему должна была, она должна выдать хороший ответ — но
проверить это предлагается самостоятельно в лабораторной работе.
