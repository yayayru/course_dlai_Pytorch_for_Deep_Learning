# Конвейеры трансформаций (Transform Pipelines)

## Источники

## Контекст

В прошлом видео был построен класс `Dataset`, который систематически загружает все изображения и метки из датасета Oxford Flowers. Но доступ к данным — это только первый шаг. В этом видео решаются **проблемы качества (quality problems)** — то, что мешает "сырым" изображениям работать с моделями PyTorch. Показано, как использовать конвейер трансформаций (transformation pipeline) PyTorch для решения задач изменения размера (resizing), преобразования формата (format conversion) и нормализации (normalization). В итоге разбирается, как работают трансформации, почему важен их порядок, и как отлаживать ситуацию, когда что-то идёт не так.

## Проблема: батч не собирается

Если создать датасет и `DataLoader` так же, как в прошлом модуле, возникает ошибка:

```python
# Create the dataset
dataset = OxfordFlowersDataset('./flower_data')
dataloader = DataLoader(dataset, batch_size=4, shuffle=True)

# Try to get a batch
for images, labels in dataloader:
    print(f"Batch shape: {images.shape}")
    break
```

```
RuntimeError: stack expects each tensor to be equal size
```

Это, скорее всего, означает, что изображения имеют разную высоту и ширину. PyTorch не может собрать их в батч, если размеры не совпадают. Батч изображений должен соответствовать формату:

```
[ batch_size, channels, height, width ]
```

Если размеры не совпадают, PyTorch выдаёт ошибку.

## Диагностика: два разных типа проблем

Проверка нескольких изображений показывает, что они действительно разного размера:

```python
# Check a few images
for i in [0, 100, 500]:
    img, _ = dataset[i]
    print(f"Image {i}: {img.size}")
```

```
Image 0: (591, 500)
Image 100: (588, 500)
Image 500: (667, 500)
```

Все разные — вероятно, снимки сделаны разными камерами за разные годы, поэтому такая вариация ожидаема.

Проверка типа данных:

```python
for i in [0, 100, 500]:
    img, _ = dataset[i]
    print(f"Type: {type(img)}")
```

```
Type: <class 'PIL.JpegImagePlugin.JpegImageFile'>
```

Итак, есть **две разные проблемы**: (1) разные размеры изображений, и (2) неверный формат — получаются изображения **PIL/pillow**, а модели PyTorch ожидают **тензоры (tensors)**. Именно для решения таких проблем в чистом, единообразном виде и предназначена система трансформаций PyTorch (transform system).

## Изменение размера изображений (Resize)

Первая попытка — привести все изображения к 224×224:

```python
transform = transforms.Resize((224, 224))
```

Проблема: если изображение прямоугольное, это исказит изображение — растянет и сожмёт его (distortion), нарушая пропорции.

Лучший подход — вызвать `Resize` с **одним** значением: это масштабирует **более короткую сторону**, сохраняя пропорции (aspect ratio). Затем с помощью `CenterCrop` можно вырезать квадрат из центра:

```python
transform = transforms.Compose([
    transforms.Resize(256),      # Resize shorter edge to 256
    transforms.CenterCrop(224),  # Extract 224x224 center square
])
```

```python
img, _ = dataset[0]
resized = transforms.Resize(256)(img)
print(f"After resize: {resized.size}")  # (302, 256) - keeps aspect ratio!

cropped = transforms.CenterCrop(224)(resized)
print(f"After crop: {cropped.size}")    # (224, 224) - perfect square
```

**Внимание на именование**: если назвать свою переменную с трансформацией `transforms` (с "s" на конце), она перезапишет сам модуль PyTorch `transforms`, что приведёт к запутанным ошибкам.

**Совет по отладке**: при построении конвейеров трансформаций тестируйте каждый шаг по отдельности, чтобы точно видеть, что происходит на каждом этапе. Проверка каждого шага таким образом — ключ к отладке трансформаций: так можно точно увидеть, как меняются данные, и поймать проблемы на раннем этапе.

## Преобразование в тензор: `ToTensor`

Следующий шаг — конвертировать изображения pillow в тензоры. `toTensor` уже встречался ранее, но стоит внимательнее рассмотреть, что именно он делает.

```python
img_tensor = transforms.ToTensor()(img)

print(f"Image size: PIL {img.size}")
# Image Size: PIL (224, 224)

print(f"Tensor Size: {tensor.shape}")
# Tensor Size: torch.Size([3, 224, 224])

# red channel, top 3x3 values
print(img_tensor[0, :3, :3])
# tensor([[0.3569, 0.4157, 0.5020],
#         [0.3922, 0.4784, 0.5490],
#         [0.3725, 0.4314, 0.5176]])
```

`ToTensor` делает две вещи:

1. Превращает изображение в тензор, при этом переставляя размерности — добавляется слой каналов (channels) для трёх цветовых каналов: red, green, blue (форма становится `[3, H, W]`).
2. Значения пикселей, обычно находящиеся в диапазоне 0–255, масштабируются делением на 255, так что все значения оказываются в диапазоне **0–1** — те же пиксельные данные, но в другом масштабе.

### Почему масштабирование помогает

- Полезно, когда все признаки (features) находятся в одном масштабе. Пример: увеличение возраста на 10 лет — это много, а добавление 10 миллиметров к росту — это почти ничего, но модель в обоих случаях видит просто число "10". При масштабировании всего в диапазон 0–1 изменение на 10% всегда означает 10%, независимо от единиц измерения.
- Нейросети выполняют много операций умножения, и большие числа вроде 255 могут легко "взрываться" (explode). Масштабирование помогает сохранять математику стабильной.

## Нормализация (Normalize)

Хотя после `ToTensor` значения интенсивности лежат в диапазоне 0–1, если изображения в основном светлые (яркие цветы), значения будут скапливаться близко к 1; если фон в основном тёмный — близко к 0. Это оставляет много неиспользуемого пространства, "сжимая" важные детали в узкий диапазон, что затрудняет для модели различение тонких отличий.

Нормализация с использованием среднего (mean) и стандартного отклонения (std) более равномерно распределяет значения. Приведённые значения были заранее подобраны так, чтобы хорошо работать в данном случае:

```python
transform = transforms.Compose([
    transforms.Resize(256),
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406],
                          std=[0.229, 0.224, 0.225])
])
```

После нормализации значения интенсивности имеют нужную форму, масштаб и распределение, что облегчает сети выделение значимых признаков.

## "Мост" тензоров (The Tensor Bridge)

При построении конвейера трансформаций важно знать, какой тип данных ожидает каждая трансформация. До вызова `ToTensor` работа идёт с обычным изображением; `ToTensor` действует как **мост**: после его пересечения вы оказываетесь "в мире тензоров" ("tensor land"), и некоторые трансформации имеют смысл только по одну сторону от этого моста.

Раньше трансформации изображений вроде `Resize` или `CenterCrop` работали только с изображениями — попытка использовать их после конвертации в тензор приводила к ошибке. Сейчас **TorchVision стал более гибким**: многие трансформации изображений теперь работают по обе стороны "моста", но это не всегда так. Например, `Normalize` работает **только** с тензорами и выдаст ошибку при попытке применить её к изображению.

Нужно быть внимательным к тому, по какую сторону "моста" `ToTensor` находится каждая трансформация, чтобы использовать их правильно и избежать скрытых (subtle) ошибок в конвейере.

## Полный конвейер трансформаций и добавление его в датасет

```python
class OxfordFlowersDataset(Dataset):
    def __init__(self, root_dir, transform=None):
        # ... previous code ...
        self.transform = transform

    def __getitem__(self, idx):
        # ... previous code ...
        if self.transform:
            image = self.transform(image)
        return image, label

# Create dataset with transforms
dataset = OxfordFlowersDataset('./flower_data', transform=transform)

# Complete pipeline:
transform = transforms.Compose([
    transforms.Resize(256),
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406],
                          std=[0.229, 0.224, 0.225])
])
```

Момент истины — можно ли наконец собрать батч, который раньше вызывал ошибку:

```python
dataloader = DataLoader(dataset, batch_size=4, shuffle=True)
for images, labels in dataloader:
    print(f"Success! Batch shape: {images.shape}")
    break
```

```
Success! Batch shape: torch.Size([4, 3, 224, 224])
```

Теперь батч содержит 4 изображения, у каждого 3 цветовых канала, и все ровно 224×224. Значения правильно нормализованы, и датасет Oxford Flowers, вероятно, готов к обучению.

## Совет по отладке

При построении конвейеров трансформаций можно взять одно изображение из датасета, применить трансформацию и проверить, как оно выглядит на каждом шаге. Если что-то выглядит неправильно, можно достать "сырое" (raw) изображение из датасета и отладить проблему, применяя трансформации по одной за раз:

```python
raw_dataset = OxfordFlowersDataset('./flower_data', transform=None)
raw_img, label = raw_dataset[0]

img = transforms.Resize(256)(img)
print(f"After resize: {img.size}")

img = transforms.CenterCrop(224)(img)
print(f"After crop: {img.size}")

img = transforms.ToTensor()(img)
print(f"After ToTensor: {img.shape}, range [{img.min():.1f}, {img.max():.1f}]")
```

```
After resize: (302, 256)
After crop: (224, 224)
After ToTensor: torch.Size([3, 224, 224]), range [0.0, 1.0]
```

Такой подход экономит массу часов отладки.
