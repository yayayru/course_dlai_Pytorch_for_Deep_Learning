## Каждый tensor и модель живут на устройстве
По мере более активной работы с тензорами (tensors) и моделями в PyTorch важно рано понять один момент: каждый tensor и каждая модель находятся на определённом устройстве (device). Это может быть CPU, GPU или другой ускоритель (accelerator), если он доступен.

**Ключевой момент: PyTorch не перемещает данные между устройствами автоматически.** Если тензоры и модель не находятся на одном и том же устройстве, код может не запуститься — он может упасть с ошибкой вида:
```
RuntimeError: Expected all tensors to be on the same device
```

В этом видео рассматривается, как контролировать, где живут данные и вычисления, и как избежать одной из самых распространённых ошибок, с которыми сталкиваются новички в PyTorch.

## CPU и GPU
У каждого компьютера есть CPU — это устройство, которое PyTorch использует по умолчанию, если не указано иное. CPU созданы для универсальной работы (general purpose work) и выполняют операции последовательно (sequentially).

Но у некоторых систем есть ускоритель, например GPU (graphics processing unit) — графический процессор, который может выполнять операции над тензорами значительно быстрее, особенно во время обучения.

> Обучение на ускорителе вроде GPU может быть **в 10–15 раз быстрее**, чем на одном лишь CPU.

Поэтому если в системе есть такой ускоритель, почти всегда стоит его использовать. Но нужно убедиться, что модель и данные находятся на одном и том же устройстве, и делать это приходится вручную.

## Проверка доступности ускорителя
```python
torch.cuda.is_available()
```
Если возвращается `True`, значит PyTorch может использовать GPU для ускорения вычислений.

Распространённый паттерн выбора устройства:
```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
```
Это выставляет `device` в `"cuda"`, если GPU доступен, и в `"cpu"` в противном случае. Это безопасное значение по умолчанию, и такой паттерн часто встречается в коде на PyTorch.

Ключевое слово `"cuda"` относится к GPU от NVIDIA, у которых есть набор инструментов CUDA. Есть и другие варианты, например `MPS` для Apple Silicon, но CUDA — самый распространённый вариант, и именно его используют лабораторные работы (labs) этого курса.

## Перенос модели и данных на устройство
После того как `device` определён, следующий шаг — перенести на него модель и данные.

Модель переносится сразу при её создании:
```python
model = MyModel().to(device)
```
Это помещает параметры модели на выбранное устройство.

Внутри training loop на устройство переносится каждый батч данных:
```python
for inputs, targets in dataloader:
    inputs = inputs.to(device)
    targets = targets.to(device)
```

## Проверка, на каком устройстве находится объект
```python
# For tensors
print(inputs.device)

# For models
print(next(model.parameters()).device)
```
Для тензоров всё довольно просто. С моделями немного иначе: сама модель не «находится» на устройстве, но её параметры — да. Поэтому можно проверить один параметр, чтобы понять, где находятся все остальные.

Если возникают ошибки, связанные с устройством, также стоит проверить, что targets и output модели находятся на том же устройстве.

## Частая ошибка: `.to()` не изменяет tensor «на месте»
```python
x.to(device)  # This looks like it moves x—but it doesn't

x = x.to(device)
```
`.to()` не изменяет tensor in place (на месте) — он на самом деле создаёт новый tensor. Поэтому если действительно нужно переместить tensor, результат нужно переприсвоить переменной. При любом использовании `.to()` важно убедиться, что результат присваивается той переменной, которая реально будет использоваться далее.

## Полный training loop с управлением устройствами
```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = MyModel().to(device)
optimizer = optim.Adam(model.parameters())
loss_function = nn.CrossEntropyLoss()

for inputs, targets in dataloader:
    inputs = inputs.to(device)
    targets = targets.to(device)

    optimizer.zero_grad()
    outputs = model(inputs)
    loss = loss_function(outputs, targets)
    loss.backward()
    optimizer.step()
```
Ключевые шаги: выбрать устройство заранее (up front), перенести модель один раз, а данные — переносить в каждом батче. Этот паттерн — основа для каждого training-скрипта, который будет написан на PyTorch.

## Ограниченная память GPU
Даже когда всё находится на нужном устройстве, есть ещё один момент, за которым нужно следить, — память GPU, потому что она ограничена. Если модель и batch size вместе занимают больше памяти, чем доступно на GPU, появится ошибка вида:
```
CUDA out of memory
```

Именно поэтому важен batch size:
- маленькие батчи делают обучение медленным;
- слишком большие батчи могут превысить объём памяти GPU и вызвать сбой (crash).

Для многих систем **batch size от 32 до 64** — хорошая отправная точка, хотя это зависит от конкретного оборудования и архитектуры модели. Если появляется ошибка нехватки памяти, для начала стоит попробовать уменьшить batch size — это самое частое решение.
