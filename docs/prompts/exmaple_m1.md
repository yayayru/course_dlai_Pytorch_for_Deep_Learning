# Основной шаблон промпта

Сконспектируй материалы модуля `theory\Module_5_Patterns_for_Highly_Autonomous_Agents`.

Обработай:

- непустые файлы транскрипций `theory\Module_5_Patterns_for_Highly_Autonomous_Agents\*.trans.txt`;
- code-файлы модуля `theory\Module_5_Patterns_for_Highly_Autonomous_Agents\*_code_*.md`, если в них есть путь к notebook, Python-файлу или папке с notebook/Python-кодом.

Для каждого непустого файла транскрипции создай отдельный файл заметок с тем же именем, заменив `.trans.txt` на `.notes.md`, например:
`01_lec_Name.trans.txt` → `01_lec_Name.notes.md`.

Если файл транскрипции пустой, не создавай для него `.notes.md` и не заполняй конспект по презентации вместо транскрипции. В итоговом сообщении только укажи, какие транскрипции были пустыми и пропущены.

Для code-файлов не создавай отдельный `.notes.md`. Изучи связанный notebook-код и/или Python-код и добавь конспект прямо в соответствующий `.md` файл, сохранив исходную ссылку на notebook, Python-файл или папку.

## Источники

- Основной источник для каждой лекции — соответствующий `.trans.txt`.
- Дополнительный источник для всего модуля — `theory\Module_5_Patterns_for_Highly_Autonomous_Agents\slides_M5.pdf`.
- Используй презентацию только для сверки структуры, терминов, схем, формул, имён, дат, чисел и очевидных ошибок распознавания речи.
- Не заменяй содержание транскрипции содержанием презентации, если транскрипция не пустая.
- Если транскрипция пустая, пропусти ее и не используй презентацию как замену отсутствующей транскрипции.
- Для code-файлов основной источник — notebook `.ipynb` и/или Python-код `.py`, путь к которому указан в `.md`.
- Если в code-файле указан путь к папке, найди в этой папке релевантные `.ipynb` и `.py` файлы и изучи их.
- Если notebook или Python-код использует локальные вспомогательные файлы, например `utils.py`, изучи их как дополнительный источник для понимания кода.
- Не запускай notebook, Python-скрипты или отдельные ячейки без отдельного указания; изучай код, markdown-ячейки и видимые outputs статически.

## Ограничения

- Не добавляй факты, которых нет в транскрипции или презентации.
- Не придумывай объяснения, примеры, выводы, связи или интерпретации от себя.
- Не объединяй информацию из разных лекций без прямого основания.
- Не сокращай материал до краткого summary.
- Не теряй существенную информацию.
- Сохраняй определения, аргументы, этапы процессов, ограничения, примеры, имена, даты, числа, термины и выводы.
- Удаляй только слова-паразиты, технические реплики, бессодержательные фрагменты и явные повторы.
- Исправляй ошибки распознавания речи только если исправление подтверждается контекстом или презентацией.
- Неуверенные, противоречивые или неразборчивые места помечай как `[неясно]`.

## Формат результата

Оформляй каждый `.notes.md` в Markdown.

В каждом `.notes.md` для лекции используй структуру:

1. Заголовок лекции.
2. Раздел `Источники`.
3. Содержательные разделы и подзаголовки по логике лекции.
4. Списки там, где перечисляются этапы, компоненты, свойства, примеры или ограничения.
5. Отдельные блоки для важных определений, процессов и выводов.

В каждом code-файле `.md` сохрани исходную ссылку на notebook, Python-файл или папку и добавь раздел `## Конспект по коду`. В этом разделе опиши:

- назначение notebook или Python-кода;
- ключевые импорты, настройки и зависимости, если они важны для понимания;
- основные шаги кода в порядке выполнения;
- важные функции, классы, переменные, prompts, API calls и структуры данных;
- что демонстрирует каждая значимая часть notebook или Python-кода;
- видимые результаты и выводы, если они есть в notebook outputs или комментариях/логике кода;
- ограничения, предпосылки и места, где требуется пользовательский ключ, модель, данные или внешний сервис.

Пиши основной текст конспекта на русском языке.

Ключевые термины курса сохраняй на английском, если они являются устойчивыми терминами: `Retrieval Augmented Generation`, `RAG`, `LLM`, `retriever`, `knowledge base`, `augmented prompt`, `context window`, `hallucination`, `vector database`.

Не оставляй целые английские предложения и фразы из транскрипции без необходимости. Переводи объяснения, аргументы, примеры и выводы на русский язык. Английский оставляй только для терминов, названий, имен, цитат, кода и коротких оригинальных формулировок, если перевод может исказить смысл.

Если термин впервые встречается, можно дать его в формате: `retriever` — компонент RAG-системы, который ищет релевантные документы в `knowledge base`. Дальше используй выбранный вариант последовательно.

## Проверка качества

После создания файлов проверь:

- что для каждого непустого `.trans.txt` создан соответствующий `.notes.md`;
- что для пустых `.trans.txt` не создан новый `.notes.md`;
- что пустые транскрипции перечислены в итоговом сообщении как пропущенные;
- что каждый code-файл с найденным `.ipynb` или `.py` обновлен прямо в своем `.md`, без создания отдельного `.notes.md`;
- что заметки не являются кратким summary;
- что презентация использована как дополнительный источник для сверки, а не как источник произвольного расширения;
- что в заметках нет неподтвержденных фактов.
